# Governance

GaussMeridian uses maintainer-led, review-driven governance during Technical Preview.

## Roles

- Contributors propose changes, review work, improve documentation, and help other users.
- Reviewers provide sustained, technically sound review in an area.
- Maintainers merge changes, manage releases and security response, enforce community policy, and protect project scope.

Roles are earned through consistent work and may be removed for inactivity, security risk, or conduct violations. Repository permissions remain least-privilege.

## Decisions

Routine decisions happen in issues and pull requests. Material changes to public APIs, persistence, security boundaries, deployment, licensing, or governance require a written proposal with alternatives, migration effects, and explicit maintainer approval.

Maintainers seek practical consensus. When consensus does not emerge, the repository owner makes the final decision and records the rationale. Security embargoes may temporarily limit public discussion.

## Releases

Only maintainers may approve the protected release environment. A release requires a reviewed source revision, passing required checks, signed artifacts, provenance, an SBOM, release notes, and completed legal notices. Releases must not be created from an unreviewed working tree.

## Changes to governance

Governance changes use a pull request and a public review period appropriate to their impact. Emergency security controls may take effect immediately and must be documented afterward.
